# SmartOnboard Design Philosophy

This document defines the immutable design principles that govern SmartOnboard. Every landing page section, dashboard, recruiter workflow, candidate experience, and marketing page must be evaluated against these principles.

## 1. Truth is Assembled, Not Generated
SmartOnboard is built on verification. We do not use "generative AI" aesthetics (glowing brains, magic dust, mysterious black boxes). Our AI does not generate candidates; it uncovers the truth.
*   **Visual Rule:** Use physics, gravity, and structural alignment to show information organizing itself into clarity. Truth should feel inevitable.
*   **Rejection of Tropes:** No glassmorphism. No mesh gradients. No abstract nodes connecting to other nodes. No particles.

## 2. The Question-Driven Narrative
We do not build "sections" or "pages." We build screens that answer exactly one question.
The narrative must flow sequentially:
*   **Why trust us?** (Because truth is assembled from evidence).
*   **Why do current tools fail?** (Because they parse keywords, not reality).
*   **How does SmartOnboard fix it?** (Evidence before intelligence).
*   **Why can you believe it?** (Because you can see the verification mechanics).

## 3. Progressive Disclosure
Never overwhelm the user. Every screen should answer exactly one question, and every answer should naturally invite the next question. 
*   **Visual Rule:** The interface should become progressively richer and more concrete as the user scrolls. 
*   **The Evolving Anchor:** Core objects (like the Intelligence Report) should persist and evolve. Rather than introducing new UI components, reveal deeper layers of the existing ones. The visitor's understanding of the interface should grow alongside their confidence.

## 4. The 90/10 Rule
*   **90% Timeless, Editorial Design:** Clean typography, spatial depth, strict brand palette (Black, White, Red, Blue, Green), and absolute clarity.
*   **10% Signature Interaction:** Unforgettable, physics-based motion that demonstrates intelligence rather than just describing it.

## 5. Absolute Clarity Over Metaphor
The emotional, metaphorical hook is earned once (at the beginning). Everything that follows must be ruthlessly concrete. If a visitor spends 20 seconds on a screen and cannot explain *exactly* what the product does, the design is too abstract and has failed.

## 6. Honest Comparisons
When comparing SmartOnboard to legacy systems, do not caricature the legacy systems. Represent them honestly (e.g., they are excellent at keyword extraction). Highlighting a genuine gap in a competent legacy system is infinitely more persuasive than mocking an incompetent strawman.
